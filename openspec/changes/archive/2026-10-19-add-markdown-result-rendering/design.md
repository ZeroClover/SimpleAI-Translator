# Design

## Context

动机与交付范围见 [proposal.md](proposal.md)。`Translator.tsx` 持有唯一的 `translatedText`，目前将其按 `\n` 分行显示；结果工具栏已有右对齐的重试、朗读、桌面插入和复制。`CopyButton.tsx` 已将传入字符串以 `text/plain` 复制，缓存和历史也存字符串。`react-markdown@10` 已在依赖中，更新窗口已有使用，所安装版本的 README 明确支持 CommonMark、默认转义 HTML 和组件映射。

`useSettings` 负责共享 UI 状态，`utils.setSettings` 负责持久化；设置读取和保存使用已知 key 列表与归一化函数。翻译回调通过 `useDeepCompareCallback` 依赖整个 `settings`，其变化会触发执行翻译的 effect，因此新增显示偏好必须与请求依赖隔离。

## Goals / Non-Goals

**Goals:**

-   保持一个权威译文字符串，让 Markdown 成为可即时切换的展示方式。
-   明确切换控件的位置、状态语义、持久化范围和键盘交互，覆盖共享翻译界面。
-   保持当前流式刷新节奏与结果操作，确保模型内容仅作为数据展示。

**Non-Goals:**

-   不要求模型主动生成 Markdown，不改变 Prompt、协议、JSON schema 或结构化输出格式化逻辑。
-   不增加 Markdown 编辑器、富文本复制、逐代码块复制、GFM 表格/删除线/任务列表、公式、图表、语法高亮或插件系统。
-   不渲染输入框、错误消息或历史列表预览；历史恢复到主结果区后，按当前偏好显示。
-   不增加逐模型、逐条历史或逐窗口的偏好，不新建同步机制或存储迁移。

## Decisions

### 1. 在结果工具栏提供图标切换按钮

位置与逻辑顺序固定为：`[Markdown]  弹性空白  [重试] [朗读] [插入，仅 Tauri] [复制]`。这延续现有工具栏结构，把显示方式与右侧结果操作区分开。工具栏在 `translatedText` 非空时显示；首个文本抵达后即可切换，包括加载、停止或保留部分结果的错误状态。无译文时不另造空工具栏，已有偏好仍应用于下一次输出。

使用现有图标库的 Markdown 图标，包在原生 `button type="button"` 或输出同等语义的现有 Button 中。关闭时为中性色；开启时使用主题强调色与持续的选中背景/边框，区别于 hover/focus，不能只靠颜色。提供 `aria-pressed`、稳定的可访问名称“Markdown 渲染”、可见焦点环，以及状态和下一步操作的 tooltip：“Markdown 渲染已关闭，点击开启”/“Markdown 渲染已开启，点击关闭”。Tab 聚焦，Enter/Space 切换，切换后保留焦点且不提交输入。按钮至少有 28×28 CSS px 的点击区；窄窗口允许工具栏换行，但保持顺序、复制可达且无水平溢出。所有新增文案同步六种 locale。

点击区尺寸仅约束新增按钮，不要求调整其它按钮。窄窗口验收使用当前 Tauri 窗口配置的最小宽度与扩展/用户脚本卡片的现有宽度约束，不引入新的窗口最小尺寸。

| 方案                   | 优点                               | 代价与结论                         |
| ---------------------- | ---------------------------------- | ---------------------------------- |
| 设置页传统 Switch      | 标签直观，适合低频偏好             | 切换当前译文需离开阅读位置；不选   |
| 主界面带标签 Switch    | 含义明确、易发现                   | 在紧凑结果工具栏占用较多宽度；不选 |
| 结果工具栏图标切换按钮 | 就近即时切换，符合现有图标操作密度 | 需要清晰状态与可访问名称；采用     |

设置页不再提供第二个入口，避免同一偏好出现两个控件。按钮的可发现性通过 Markdown 标志、状态 tooltip 与键盘语义解决；它是阅读偏好，不属于 Provider 的输出控制。

### 2. 将偏好纳入现有设置，同时隔离翻译执行

新增 `ISettings.renderMarkdown: boolean`，只有存储值严格为 `true` 才启用，其余值归一化为 `false`。把 key 纳入 `settingKeys`、`normalizeSettings` 与已有保存路径，使用现有 `useSettings` 更新 UI 并持久化。按已有设置的存储作用域记住选择；重新打开界面时读取已保存值，不承诺新的跨窗口实时广播。设置页保存其它项时必须保留这个不在表单中的字段。

具体覆盖设置页的 `onSubmit` 和失焦保存路径：合并非表单的 `renderMarkdown` 时以当前存储值为准，不能将设置页旧快照里的值写回。沿用现有读取/保存设施，并在当前 UI 状态中保留该值，不增加跨窗口广播框架。

用户脚本同样复用 Translator，且现有 `polyfills/userscript.ts` 的存储 `set` 以 `value && GM.setValue(...)` 过滤值、通过异步 `forEach` 写入，既会丢弃 `false`，也不会等待保存结束。此变更须最小修正该适配器：仅跳过 `undefined`，其余传入值（包括 `false`、`null`、`0` 和空字符串）均保存，并等待全部写入完成，使“开启 → 关闭 → 重新打开”确实保持关闭。其余用户脚本行为不在本次调整范围。

在接入按钮前，收窄 `translateText` 的依赖：由已经解析的 Provider/Model 和请求实际使用的输出控制构成稳定的请求相关值，不把 `renderMarkdown` 或整个 settings 对象作为触发依赖。保持真实模型、Provider 配置和输出控制变化的现有行为，不使用“跳过下一次翻译”标志绕过 effect；否则可能吞掉随后的合法提交。切换不得调用 `setTranslateDeps`、重试、清空结果或中止当前 controller。缓存 key 不加入显示偏好。

同时收窄从 settings 同步 `selectedModel` 的 effect：它只能响应真正影响默认模型选择的值变化，不能因纯显示偏好更新而重新应用默认模型。历史恢复允许当前模型与持久化默认模型不同；默认 A、恢复 B 后切换 Markdown，必须保持 B 和恢复的译文，不触发 `selectedModel → translateDeps → translateText` 间接链路。请求回调和模型同步两处都要隔离，不能只修改前者。

只调整实现这一隔离所需的依赖，不借此重构翻译生命周期。持久化沿用现有设施，不增加额外存储键副本或历史模式字段。

### 3. 单一原文，派生显示

关闭分支沿用现有逐行纯文本。开启分支把完整、当前已刷新的 `translatedText` 交给一个局部 Markdown 结果组件，避免逐行解析破坏跨行列表和代码块。组件只接收文本、主题/字号等展示参数，不写回译文状态、不发请求、不存 HTML。

`CopyButton text={translatedText}` 保持原数据流；朗读、插入、语言互换、缓存和历史继续使用同一字符串。这里的“原始文本”是现有引擎经 thinking 过滤、必要的结构化格式化后交给 UI 的文本，不是 SSE、JSON 或未过滤模型响应。复制不得使用 DOM `innerText`/`textContent`、序列化 HTML，也不得 trim 或移除 Markdown 标记。

结构化开关与 Markdown 开关完全独立。现有结构化输出一次性发出的可读文本可被渲染；若 `stream-structured-output` 日后提供增量文本或完整替换，也经过相同展示分支，本变更不承担 JSON 解析。

### 4. 使用现有 CommonMark 渲染，限制主动内容

采用 `react-markdown` 默认 CommonMark 能力：标题、段落、强调、有序/无序列表、引用、行内代码、围栏/缩进代码块和分隔线。结果组件用一个小型 remark 转换把文本中的软换行改为硬换行（不新增依赖，也不是第二个解析器），使段落和列表项内的单换行都保持可见；不对段落使用 `white-space: pre-wrap`，以免硬换行后的换行符再产生空行。代码区保留空白与换行。样式继承主题、字号和现有语言方向，不覆盖其它界面；长代码块局部横向滚动，长文本换行，容器不被撑宽。

原始 HTML 按库默认方式显示为文字，不安装 `rehype-raw`，不使用 `dangerouslySetInnerHTML`。保留默认 URL 过滤，并用组件映射把链接展示为非交互标签文字、把图片展示为 alt 文字（空 alt 时不显示），不生成可导航链接或实际图片。这样在扩展与 Tauri 中采用同一行为，不因翻译内容主动请求图片，也不引入应用内导航、脚本协议或 native shell 跳转路径。查看链接地址或完整图片语法时可关闭渲染或复制原文。这个首版范围是阅读排版，不包含链接访问和媒体预览。

不添加 GFM/高亮等依赖，也不为流式输出引入第二个 Markdown 解析器、手工补齐标记或 AST 缓存。

### 5. 接受流式语法逐步成形

沿用 UI 最多每 100ms 合并刷新一次，以及完整替换/结束时立即刷新的机制。每次从完整的当前字符串派生渲染，未闭合强调、链接或代码围栏使用解析器当前解释，允许后续文本到来时重新排版，不篡改或等待补全原文。加载指示放在 Markdown 树之外，避免作为字符送入解析器或进入复制内容。

切换只重新渲染当前状态，后续增量继续进入同一请求缓冲区。停止、失败时保留的文本仍可切换与复制，不因渲染而进入成功缓存/历史。已有缓存命中或历史恢复显示时，使用当前偏好。

## Risks / Trade-offs

-   图标初次使用不如文字 Switch 直观 → 使用 Markdown 标志、状态 tooltip、可访问名称和非仅颜色的选中态；窄界面验收操作可达。
-   每次刷新解析完整文本、流式语法可能重排 → 复用现有刷新频率，用长段落与未闭合代码块验证交互，不先引入增量解析器或性能配置。
-   展示设置更新可能重启当前翻译 → 请求依赖隔离，并用受控流验证切换前后请求数、abort 状态与最终内容。
-   部分 CommonMark 排版会改变普通词典文本的视觉结构 → 默认关闭、即时恢复原文；结构化 JSON 格式化逻辑不变。
-   链接和图片采用文本展示，GFM 不在首版范围 → 在规格和验收中明确支持边界；原始内容始终可复制。

## Migration Plan

无需数据迁移。缺少字段的现有设置自动按关闭处理，新选择通过原有设置保存。实现时先落地设置与请求依赖隔离，再接入渲染及按钮，最后补充场景测试并合并增量规格。若撤回本功能，删除新增显示分支、按钮及字段即可，不引入兼容路径。
