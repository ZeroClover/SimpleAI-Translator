## Notes by group

- 2.7: the script (key in `en/translation.json` with no `'key'`, `"key"` or `` `key` `` literal in `src/**/*.{ts,tsx}`) found 38 unused keys after 2.2 and 2.3, not the 28 + 4 estimated. The extra ones are `Days` (DurationPicker) and keys whose only remaining reference was not a `t()` call (for example `is required`, built with a template string in `Form`). All 38 were removed from all 6 locales.
- 3.x: `src/tauri/bindings.ts` is regenerated by running the debug binary (`target/debug/app --silently`, with `SIMPLEAI_TRANSLATOR_IPC_SOCKET` pointed at a scratch path): the export runs at the top of `main()`, and the process then exits through the single-instance plugin. The file is formatted with Prettier afterwards.
- 3.3 / 3.5: `cargo check` for `x86_64-pc-windows-msvc` and `x86_64-unknown-linux-gnu` cannot run on this Mac (`ring` needs an MSVC C toolchain; the GTK `*-sys` crates need a Linux sysroot). Windows and Linux compilation is left to the `test-build` CI matrix.
- 4.2: Rust integration tests with a local TCP server cover: no response head (cancel returns `AbortError` and the server sees the connection close), a paused chunked body (the server sees the close within 2 s; with the `fetch_cancel` call removed this test fails), a cancel that arrives before `fetch` registers, a complete body with a multi-byte character, a 400 response, and a refused connection. The body channel is `Channel<FetchBodyMessage>`: a local type whose `IpcResponse` sends chunks as `InvokeResponseBody::Raw` and the end as `{ done }` / `{ error }`. `Channel<InvokeResponseBody>` itself cannot be used because `InvokeResponseBody` has no `specta::Type`; the message type is typed as `unknown` in the bindings.
- 4.2: a `fetch_cancel` for an id that is not registered leaves a "requested" marker so a cancel that overtakes `fetch` still stops it. `tauriFetch` calls `fetch_cancel` only while the request has not finished; the only way to leave a stale marker is an abort in the instant between Rust sending the end of the body and JavaScript receiving it, which costs one short string.
- 4.3: `tauriFetch` reads the request body before its abort check, so nothing awaits between the check and registering the abort listener; an abort while the body was read used to be missed (found in review; regression test "does not start a request that was aborted while its body was read" fails on the old order).
- 4.3: `tauriFetch` creates the body stream and the channel handler before `invoke`, so chunks that arrive before the response head are queued in the stream (unit test "keeps body chunks that arrive before the response head").
- 4.4: `fetchSSE` checks the signal after every `read()` and right after obtaining the reader (an abort during `fetcher` fired before there was a reader to cancel).
- 4.6: `git grep 'http:default' -- src-tauri` still matches `src-tauri/gen/schemas/{linux,windows}-schema.json`. Those are written only by `tauri build` on Linux and Windows and were already stale (they still list the `fs` and `os` plugins); the macOS build regenerated the other schema files.
- 5.5: the settings panel diff skips fields whose form value is `undefined` (for example `runAtStartup` before the autostart query fills it in). Such a value cannot be persisted (JSON drops it), and without the rule an untouched form wrote `runAtStartup` on Save. E2e cases cover "Save without changes writes nothing", "only the changed field is written over a newer `defaultModel`", deleting or switching to Anthropic the Provider linked to OpenAI TTS (one write, Edge fallback, matching toast), and deleting a Provider after another window saved system TTS. The Markdown e2e covers the stale-snapshot scenario on both save paths and checks that a saved theme applies at once.
- 6.5: e2e checks that "Saved" appears exactly once in the Translator's embedded settings and on the extension options page (production WXT build), and that the history window shows its copy toast (that test fails without the new `Toaster`). The desktop settings window was not run.
- 7.7: `edge-tts.spec.ts` mocks `../utils` with only `isTauri` instead of spreading `vi.importActual('../utils')`: once `tts/index.ts` no longer imported `../utils` first, the actual-module import inside the mock factory deadlocked on the import cycle `utils → universal-fetch → background/fetch → utils`.
- 9.2: `check_update` returns `Result<Option<UpdateResult>, tauri_plugin_updater::Error>` instead of `Option<UpdateResult>`, because callers must tell a failed check (record nothing, send no event) from "no update". It records the result under one lock and rebuilds the tray only when the update entry appears or disappears; the updater window's own check records its result too.
- 9.1: the three `get_or_create_window` calls keep the old titles and sizes: History 760×720 (min 660×600), Settings 660×800 (min 660×600), Updater 500×500 (min 200×200).
- 9.4: the no-updater build contains no updater archive or signature, and its `Info.plist` has the base `CFBundleIdentifier`, name and version (1.6.0; the old full copy still said 1.5.1). `bundle.windows.signCommand: null` removes the key by JSON merge patch; the Windows build runs in CI.
- 10.1: Node 24 (Krypton) is the Active LTS on 2026-10-19; Node 26 becomes LTS on 2026-10-28. The five workflows use `NODE_VERSION: 24`, `package.json` has `engines.node: ">=24"`, and README / README-CN / AGENTS state the requirement.
- 10.2: breaking changes handled: rand `RngCore` / `thread_rng` → `Rng` / `rng`; sha2 0.11 output has no `UpperHex` (hex built per byte); reqwest-websocket `RequestBuilderExt` → `Upgrade`; specta's `Type::definition`; the TypeScript exporter lost its formatter option (bindings are formatted with Prettier). The new tauri-specta generator writes `bindings.ts` in a different style; command names, arguments and the `{ status: 'ok' | 'error' }` results are unchanged. `rust-version` is 1.90 (MSRV of tauri 2.12). `cocoa` 0.27 deprecates its whole API, so it was replaced (D10): `insertion.rs` uses `objc2-app-kit` 0.3.2 (already in the tree through tao/wry), and the per-window `cocoa` block in `windows.rs` was dropped because Tauri already disables automatic window tabbing without a tabbing identifier and `set_visible_on_all_workspaces(true)` already sets `CanJoinAllSpaces`. `ActivateIgnoringOtherApps` is deprecated (no effect from macOS 14) and kept with `#[allow(deprecated)]` for older macOS. The Windows-only code compiles against `windows` 0.62: every function it calls has the same signature in 0.61.3 and 0.62.2.
- 11.1: `baseui-sd` cannot reach React 19: 12.2.4 declares `react < 19`, and every 14.x tarball on npm is a source dump without a build. `baseui-sd` 12.2.4 is upstream `baseui` 12.2.0 plus one change in `select/select-component.js` (outside-click checks use `event.composedPath()[0]`, so a click inside an open Select in the content script's shadow root is not treated as outside). It was replaced with upstream `baseui` 18.2.0, carrying that change as `patches/baseui@18.2.0.patch`; the e2e test "a Select in the popup card stays usable inside the shadow root" fails with the patch reverted. `pnpm.overrides` pins `@types/react` / `@types/react-dom` to 19 (`@types/react-copy-to-clipboard` pulled in 18). With Vite 4, the production build dropped the body of Base Web 18's CommonJS `select/index.js` (`sideEffects: false`), so group 11 landed on Vite 8.
- 11.1: React 19 changes: `react-draggable` already used `nodeRef`; `useRef` needs an initial value; Base Web's `inputRef` props are typed non-null (two casts); `react-error-boundary` 6 passes `error: unknown`; `eventsource-parser` 4 takes `createParser({ onEvent })`; i18next 26 interpolation takes an object; `webextension-polyfill` 0.12 types message payloads as `unknown`; `color` 5 ships its own types. Dexie 3 assigned `nativePromiseProto.then` during zone switches (the Firefox "then is read-only" error); Dexie 4.4.6 no longer does, so the content-script workaround was removed. The `RxStop` path changed in react-icons 5.7, so the e2e selector for Stop was updated.
- 12.1: comparing the saved pre-change manifests with the built ones, `manifest_version` (3 for both browsers, including the Firefox zip), name, description, version, `icons`, `action.default_icon`, `permissions`, `host_permissions`, `optional_host_permissions`, `browser_specific_settings` and the content script options are identical for Chromium and Firefox.
- 12.1: the generated manifests keep name, description, version, `icons`, `action.default_icon`, permissions, `host_permissions`, `optional_host_permissions`, `browser_specific_settings`, the content script options and an MV3 background (Chromium service worker, Firefox `background.scripts`). `web_accessible_resources` lists the card images as `assets/*.png` and `assets/*.jpg`, plus WXT's own `content-scripts/content.css`. WXT names content script assets after the entrypoint (`assets/content.png`, `assets/content.jpg`), but with two byte-identical PNGs (`icon.png` and `icon-large.png`) Rolldown sometimes named the one deduplicated file `content2.png` (about one build in seven, found in review), which an exact-name list missed. `icon-large.png` was a byte-for-byte copy of `icon.png` and was deleted (Settings imports `icon.png`), and the list matches by extension; twenty consecutive Chromium and Firefox builds then produced `content.png` and `content.jpg`. Other differences are output paths and WXT's `action.default_title` (the extension name). The images are imported with `?no-inline`, served through `chrome.runtime.getURL` in the extension, and the content script contains no image data URLs; the e2e test checks that the card's logo loads.
- 12.1: Rolldown writes non-ASCII characters as-is, and the minifier turned Dexie's `String.fromCharCode(65535)` into a raw U+FFFF. Chromium refuses to load an extension whose content script contains such a noncharacter, so the extension build sets `output.charset: 'ascii'` (esbuild escaped by default).
- 12.2: the content script registers its listeners in `main(ctx)` and imports the card module (which imports `@/common/i18n`) inside `main`; WXT inlines it into the single file. The card mounts with `createShadowRootUi` (`cssInjectionMode: 'ui'`, host element `zeroclover-simpleai-translator`, `inheritStyles: true` — a deliberate choice: the design does not set it, and WXT's default `all: initial` reset would change how the card inherits page styles compared with the old container, `isolateEvents` for the mouse and touch events the old container stopped). The `consts.ts` ids are on the elements inside the host.
- 12.3: the e2e test instruments `chrome.storage.sync.get` in the content script's isolated world over CDP: no read and no host element while no card is open, and a read on the next click once the card is open.
- 12.5 / 12.6: TypeScript 6 needs `moduleResolution: bundler` (WXT's subpath exports) and `lib: ES2022`. `vite-tsconfig-paths` was dropped for Vite 8's native `resolve.tsconfigPaths`, and the Tauri renderer uses Vite 8's default minifier (`esbuild` is no longer installed). Vitest 5 cannot construct mocks whose implementation is an arrow function, so the `EdgeTTS` mocks use `function`. Prettier 3.9 reformatted a few expressions; the new recommended rules of typescript-eslint 8 and ESLint 9's report of unused disable directives were fixed at their sites. The ESLint config turns off `react-hooks/rules-of-hooks` for Playwright fixtures (their `use` callback) and `no-require-imports` for the CommonJS `eslint.config.js`.
